## 3. 数据模型（`data.js`）

### `events` — 调研事件点（红针）

| 字段 | 说明 |
|------|------|
| `id` | 唯一 ID，如 E1、J1、U1 |
| `evt` | 场次：`0716` `0717` `0727` `0802` `0810` `0818` |
| `kind` | `closed` 断交 / `mid` 中度 / `slow` 缓行 / `ctrl` 管制 |
| `morph` | `road` `tunnel` `culvert` `slow` |
| `district` | 区县；**经开→官渡，高新→五华**（写进 `app.js` 的 `districtKey`） |
| `lat` `lng` | **GCJ-02**，与高德一致 |
| `source` | 原文出处（信息港、交警、小红书等） |

8.18 官方点 E1–E23、消防 F1–F5；用户补点 U1–U27（编号 29–55）。

### `hist` — 常年易淹 / 用户图层（蓝针）

- 带 `ref: "E1"` 的点**坐标继承**对应事件点，勿两处维护
- `cat`: `tunnel` `road` `river` `new` `ugc` `safe`

### `feedback` — 用户反馈表（不进地图或仅溯源）

| `status` | 含义 |
|----------|------|
| 已入库 | 地图上有针，有 `pin` 编号 |
| 负例不入库 | 评论说没淹 / 不是本场 / 与已有针矛盾 — **表里记一笔，不插针** |
| 存疑未入库 | 证据或坐标不够 — **暂不插针，等补图/路名** |

## 4. 页面功能（顶栏）

| 分页 | 作用 |
|------|------|
| 全部淹水 / 各场次 | 按 `evt` 筛事件点 |

## 5. 日常操作思路（我们对话里沉淀的）

### 5.1 加官方点

1. 找**一手原文**（昆明信息港、云南网、交警信息港等），不要只抄本地宝
2. 写入 `data.js` → `events`，补 `evt` / `kind` / `source`
3. 在 `app.js` 补 `PERIOD`、`NEWS` / `sourceLinksFor`（若新场次）
4. `index.html` 顶栏 +  catalog 筛选项加场次按钮
5. 坐标走 **§6**，跑 `check-coords.mjs`，再发布

### 5.2 加小红书 / 用户点

1. 笔记 + 评论交叉；**不编造**没看见的报点
2. 硬证据（视频、多评一致）→ `events` 或 `hist`（`ugc`）
3. 一条评论、坐标模糊 → `feedback` 标 **存疑未入库**
4. 说没淹 / 不是 8.18 → **负例不入库**
5. 用户反馈页 `feedback` 数组同步一行

### 5.3 改文案 / 分析页

- 区域分析幽默文案：`index.html` `#view-report` + `app.js` 里 `notes` / `taglines`
- 梯队榜：`paintDistrictTierList()` — **官渡固定「夯」**，其余按点数动态分档

### 5.4 发布

```powershell
# 仓库根「淹了么」
powershell -ExecutionPolicy Bypass -File ".\kunming-flood-map\scripts\publish.ps1"
```

成功标志：`done http://43.180.135.43:8088/ status=200`  
提醒访问者 **Ctrl+F5** 强刷。

SSH 密钥与服务器细节见维护者私发的 deploy skill，**勿提交 `*.pem`**。
